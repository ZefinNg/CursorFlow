# CursorFlow 数据存储设计

> 关联 PRD：3.1 数据持久化、3.4 导出、非功能需求
> 上游设计：[01-技术架构设计.md](01-技术架构设计.md)、[02-数据采集模块设计.md](02-数据采集模块设计.md)

## 1. 存储选型与位置

- SQLite（Qt SQL 模块自带 QSQLITE 驱动），零配置单文件。
- 数据库文件位置（跨平台对齐系统数据目录）：

| 平台 | 路径 |
|------|------|
| Windows | `%APPDATA%\CursorFlow\stats.db` |
| macOS | `~/Library/Application Support/CursorFlow/stats.db` |
| Linux | `~/.local/share/CursorFlow/stats.db` |

- 传输中/落盘不加密（数据本身无隐私内容，PRD 3.5 仅计数不记录内容）；如后续需要，可评估 SQLCipher，不纳入本期。

## 2. 表结构（DDL，继承 PRD 第 7 节）

```sql
CREATE TABLE IF NOT EXISTS daily_stats (
    date              TEXT PRIMARY KEY,      -- '2026-10-30'，本地日期 ISO 格式
    mouse_distance_m  REAL    NOT NULL DEFAULT 0,
    key_press_count   INTEGER NOT NULL DEFAULT 0,
    left_click_count  INTEGER NOT NULL DEFAULT 0,
    right_click_count INTEGER NOT NULL DEFAULT 0,
    scroll_steps      INTEGER NOT NULL DEFAULT 0,   -- 绝对值累加
    active_minutes    INTEGER NOT NULL DEFAULT 0
);

CREATE TABLE IF NOT EXISTS hourly_stats (
    id               INTEGER PRIMARY KEY AUTOINCREMENT,
    date             TEXT    NOT NULL,
    hour             INTEGER NOT NULL CHECK(hour BETWEEN 0 AND 23),
    mouse_distance_m REAL    NOT NULL DEFAULT 0,
    key_press_count  INTEGER NOT NULL DEFAULT 0,
    UNIQUE(date, hour)                                -- 幂等 UPSERT 依赖
);
CREATE INDEX IF NOT EXISTS idx_hourly_date ON hourly_stats(date);

CREATE TABLE IF NOT EXISTS meta (
    key   TEXT PRIMARY KEY,
    value TEXT NOT NULL
);
-- meta 预置：schema_version、first_run_date、privacy_accepted_at、brief_date

-- 成就表（M5 7.3 增补，07 号文档 §3.2）：已达成的成就仅记 id 与时间，
-- 幂等写入 INSERT OR IGNORE，成就定义（阈值/文案）在代码内维护
CREATE TABLE IF NOT EXISTS achievements (
    id          TEXT PRIMARY KEY,      -- 成就 id，如 'marathon'
    unlocked_at TEXT NOT NULL          -- 达成时间 ISO 格式
);

CREATE TABLE IF NOT EXISTS analogy_rules (   -- 趣味类比库（M6 增补，PRD 3.8.1）
    id        INTEGER PRIMARY KEY AUTOINCREMENT,
    kind      TEXT NOT NULL CHECK(kind IN ('distance','keystrokes')),
    ref_value REAL NOT NULL,               -- 参照基准值：米 / 次
    ref_text  TEXT NOT NULL                -- 参照物描述，如"一辆公交车的长度"
);
```

`analogy_rules` 由建库时从 qrc 资源 `analogy.json`（200 条：距离/按键各 100，
量级谱系 0.1 米 ~ 100 公里、1 ~ 100 万次）导入空表，之后只读；条目定义随产品
迭代更新资源并随版本升级重建（表可 `DROP` 重导，无用户数据）。

与 PRD 的差异说明：为 `hourly_stats` 增加 `UNIQUE(date, hour)`，将"按天分表"简化为**单表 + 索引**——数据量极小（每天 24 行，十年约 8.7 万行），单表可避免动态建表复杂度，查询与清理都更简单；按天过滤由 `date` 列承担，语义与 PRD 一致。

## 3. 写入策略

### 3.1 增量 → 内存（3 秒）
`DataManager` 收到 `deltaReady` 信号后合并进内存当日缓存 `TodayCache`（同 02 号文档 DeltaSnapshot 结构 + 日期键）。

### 3.2 内存 → SQLite（1 小时 + 关键时刻）

```
QTimer(3600s) ─┐
应用退出 flush ─┼─→ saveSnapshot(date) 执行：
手动触发     ──┘
  BEGIN;
  UPSERT daily_stats（当日累计值覆盖写）;
  UPSERT hourly_stats（当前小时行）;
  COMMIT;
```

UPSERT 语句：

```sql
INSERT INTO daily_stats(date, mouse_distance_m, key_press_count,
                        left_click_count, right_click_count, scroll_steps, active_minutes)
VALUES(?,?,?,?,?,?,?)
ON CONFLICT(date) DO UPDATE SET
    mouse_distance_m=excluded.mouse_distance_m,
    key_press_count=excluded.key_press_count,
    left_click_count=excluded.left_click_count,
    right_click_count=excluded.right_click_count,
    scroll_steps=excluded.scroll_steps,
    active_minutes=excluded.active_minutes;
```

- 采用**覆盖写**而非增量 UPDATE：以内存缓存为准，天然幂等，重复写入不会翻倍。
- 事务包裹保证两张表一致。
- PRAGMA：`journal_mode=WAL`（读写并发）、`synchronous=NORMAL`（性能与持久性平衡）。

### 3.3 数据保留与自动清理（PRD 3.4）

- `retentionDays` 默认 365，可配置。
- 每日首次 flush 后执行一次：
  `DELETE FROM daily_stats WHERE date < date('now','localtime','-N days');`
  `hourly_stats` 同理。
- 清理前可触发（可选二期）自动导出备份。

## 4. 查询接口（DataManager 暴露给 UI）

| 接口 | 返回 | 用途 |
|------|------|------|
| `todayStats()` | `TodayCache`（内存） | 仪表盘大数字 |
| `queryDaily(from, to)` | `QVariantList`（每行一个 date + 6 项指标） | 7/30 天折线图 |
| `queryHourly(date)` | 24 项 `QVariantList`（缺失小时补 0） | 热力图 |
| `queryRangeSummary(from, to)` | 聚合（SUM/AVG） | 托盘摘要、导出 |
| `statsSaved()` 信号 | — | 写库完成通知 UI/导出 |

查询均为同步执行（数据量小、主线程延迟可忽略），若未来数据量增大再迁移到工作线程。

## 5. 数据迁移与版本

- `meta.schema_version` 当前为 `1`。
- `Database::open()` 中执行升级链：`v(n-1) → v(n)` 每步一个事务；新增列用 `ALTER TABLE ... ADD COLUMN`，并为旧行回填默认值。
- 版本高于程序支持时（用户降级安装）：提示但只读运行，不做破坏性回滚。

## 6. 导出（PRD 3.4，详见 export/Exporter）

| 格式 | 内容 | 实现 |
|------|------|------|
| CSV | 指定日期区间 `daily_stats` 原始行，UTF-8 BOM（兼容 Excel 中文） | 逐行写出 |
| JSON | 同区间 daily + hourly 两数组 | QJsonDocument |

导出路径由用户选择（`QFileDialog`），完成后托盘气泡提示。

## 7. 容错与恢复

| 场景 | 处理 |
|------|------|
| 打开失败（文件锁/权限） | 提示用户路径并允许选择新位置；进程继续运行但记录内存数据 |
| 写入失败 | 重试 3 次；仍失败保留内存缓存，UI 显示离线徽标，下次 flush 重试 |
| 损坏检测（打开/查询抛 SQLITE_CORRUPT） | 将 `stats.db` 重命名为 `stats.db.corrupt-<ts>`，重建空库 |
| 进程崩溃 | 最多丢失最近 1 小时未 flush 数据（3s 内存增量 + 1h 落盘间隔），可接受 |
| 时区/夏令时 | 统一使用**本地日期**（`QDate::currentDate()`），存储不做 UTC 转换 |

## 8. 测试要点

- UPSERT 幂等性：同一快照写两次数据不翻倍。
- 跨零点 flush 归属正确性。
- 保留天数清理边界（恰好第 N 天的数据应保留）。
- 迁移链：v1 → v2 模拟列新增，旧数据不丢。
- 10 万行规模下 `queryDaily(30天)` 耗时 < 10 ms。
