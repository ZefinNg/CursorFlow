# CursorFlow 数据采集模块设计

> 关联 PRD：3.1 数据采集、3.5 隐私与安全、10 风险与对策
> 上游设计：[01-技术架构设计.md](01-技术架构设计.md)

## 1. 模块职责

在独立线程中通过平台全局钩子捕获输入事件，完成四类统计：

1. 鼠标移动物理距离（米）
2. 键盘按键次数（仅计数，不记录内容）
3. 鼠标左/右/中键点击次数
4. 滚轮滚动步数

并负责异常过滤（跳变剔除）、活跃时长推断、向 DataManager 提交增量。

## 2. 核心类设计

```cpp
// 增量缓冲区：原子计数，回调线程写，flush 读
struct DeltaBuffer {
    std::atomic<double>  distancePx{0.0};    // 像素距离累加
    std::atomic<uint32_t> keyPresses{0};
    std::atomic<uint32_t> leftClicks{0};
    std::atomic<uint32_t> rightClicks{0};
    std::atomic<uint32_t> midClicks{0};
    std::atomic<int32_t>  scrollSteps{0};    // 带符号
    std::atomic<int64_t>  lastInputMs{0};    // 最近一次输入时间戳（活跃推断）
    void reset();                            // flush 后清零
};

class InputCaptureWorker : public QObject {
    Q_OBJECT
public:
    bool start();          // 装载 IPlatformHook，注册 3s flush 定时器
    void pause();          // 托盘"暂停统计"：挂起钩子但不卸载
    void resume();
signals:
    void deltaReady(DeltaSnapshot delta);   // 每 3 秒跨线程提交
};
```

`DeltaSnapshot` 为普通 POD 结构（各计数值 + 时间区间），经排队信号投递到主线程，避免共享可变状态。

## 3. 各平台钩子实现

### 3.1 Windows（MVP 优先实现）

```cpp
HHOOK mh = SetWindowsHookEx(WH_MOUSE_LL,   MouseProc, nullptr, 0);
HHOOK kh = SetWindowsHookEx(WH_KEYBOARD_LL, KbdProc,  nullptr, 0);
```

- 低级钩子回调运行在安装线程的消息循环中 → 采集线程需运行 `QThread::exec()` 并处理 Windows 消息（`MsgWaitForMultipleObjects` 或让 Qt 消息循环派发 `WM_*`）。
- 回调必须**快速返回**（超时系统会移除钩子），回调内只做：读取坐标 / 判断按键 → 原子自增。距离计算推迟到 flush，或回调内只累加 ΔX/ΔY。
- `WM_MOUSEWHEEL` 的 `wheelDelta`（±120 一格）换算为滚动步数。
- 双击不重复计数：直接按 `WM_LBUTTONDOWN` 次数统计。
- 键盘：只统计 `WM_KEYDOWN/WM_SYSKEYDOWN` 次数，**不读取键值内容**，仅判断是否为修饰键以执行 PRD 的"组合键不重复计数"规则（详见 4.2）。

### 3.2 macOS

- `CGEventTapCreate(kCGSessionEventTap, kCGHeadInsertEventTap, kCGEventTapOptionListenOnly, ...)`，只监听不改写。
- 监听 `kCGEventMouseMoved / LeftMouseDown / RightMouseDown / OtherMouseDown / ScrollWheel / keyDown`。
- 权限：需"辅助功能"授权；启动时用 `AXIsProcessTrusted()` 检测，未授权则发引导（PRD 风险对策）。授权后事件 tap 才有数据，无需重启进程（重新创建 tap 即可）。

### 3.3 Linux（X11）

- XInput2：`XISelectEvents` 订阅根窗口的 `XI_RawMotion / XI_RawButtonPress / XI_RawKeyPress`。
- `XI_RawMotion` 携带 raw 值（valuator），累加位移。
- MVP 仅支持 X11；Wayland 环境检测到 `WAYLAND_DISPLAY` 时提示降级为"仅托盘 + 手动记录"或提示用户切换 X11 会话。

## 4. 关键算法

### 4.1 鼠标距离：像素 → 物理

```
单步距离(px)  = sqrt((x2-x1)² + (y2-y1)²)
有效判断      : 距离 ≤ 2 × max(屏幕宽, 高)     // PRD: 超过对角线2倍视为跳变
物理距离(米)  = Σ像素距离 / DPI × 25.4mm / 1000
DPI           = 用户校准值 或 96（默认）
```

- 校准输入：屏幕对角线英寸数 + 分辨率 → `PPI = sqrt(w²+h²)/inch`，1px = 25.4/PPI 毫米（PRD 3.4 校准项）。
- 多屏：使用**虚拟桌面全局坐标**（Windows 的 `GetSystemMetrics(SM_XVIRTUALSCREEN)` 等），避免坐标系切换导致负跳变；跳变剔除规则同样适用。

### 4.2 键盘计数规则（PRD：不含修饰符重复计数）

| 场景 | 计数 |
|------|------|
| 普通按键按下 | +1 |
| 按住不放（OS 自动重复） | +1（只统计首次 keydown，重复事件丢弃） |
| Ctrl+C 组合键 | +1（C 键计数；Ctrl 按下/释放不计数） |
| 纯按 Ctrl | +1（修饰键单独按下仍计一次） |

实现：维护 `lastKeyCode` 与自动重复标记；Windows 下用 `KBDLLHOOK_STRUCT.flags & LLKHF_UP` 区分按下/释放，用 `dwExtraInfo` 之外的重复检测（连续相同 vk 且无中间 up）过滤。

### 4.3 活跃时长推断

- `lastInputMs` 记录最近输入时间；任一输入事件刷新。
- 每 3 秒 flush 时：若 `now - lastInputMs ≤ 120s`（5 分钟空闲阈值可配置），本次区间记为活跃，累加进当日 `active_minutes`（以秒累计、分钟展示）。

### 4.4 滚动步数

- Windows：`wParam 高字 signed` / `WHEEL_DELTA(120)` → 步数（带方向）。
- macOS：`CGEventGetIntegerValueField(event, kCGScrollWheelEventDeltaAxis1)`。
- 存储与统计采用**绝对值累加**（PRD 要求），方向信息不落库。

## 5. 异常与边界处理

| 场景 | 处理 |
|------|------|
| 远程桌面/投屏坐标跳变 | 距离 > 2×屏幕对角线 → 丢弃该步进量（PRD 3.1） |
| 系统休眠/恢复 | 挂起时暂停采集（监听 `QSessionManager`/电源广播），恢复后重置"上次坐标"防止大跳变 |
| 钩子被系统移除 | Windows 下检测回调不再触发的超时保护；自动重装一次并上报 UI 状态 |
| 跨天零点 | flush 时按事件发生时间归属到对应日期；跨零点时拆分到两天（简化实现：以 flush 时间归属，误差 ≤3s 可接受） |
| 暂停统计 | 托盘暂停 → `pause()` 停止累加（钩子保留），恢复后重置坐标基准 |

## 6. 隐私约束（实现层强制，对应 PRD 3.5）

1. **键盘**：代码中不存在保存键值的路径 —— 回调里只 `++counter`，键值仅用于判断修饰键/重复，不进入任何缓冲区、日志或数据库。
2. **进程白名单**：不记录按键发生的窗口/进程（超出 PRD 范围）。
3. **首次启动隐私声明**：`main.cpp` 在装载钩子前弹出同意页，`QSettings` 记录 `privacyAccepted=true` 后才调用 `start()`；拒绝则仅展示空仪表盘 + 提示。
4. **审计点**：Code Review 检查项 —— 任何 `GetKeyNameText` / 字符映射类 API 均不得出现在采集路径。

> **M7 扩展（PRD 3.10.1）**：按键速度采样只记录按键时间戳，不记录键值内容。新增的 `keyTimeBuf_` 仅存储 `QDateTime::currentMSecsSinceEpoch()` 返回的整数毫秒值，vkCode 不进入该缓冲区。速度计算在采集线程内完成后丢弃原始时间戳，不写入任何持久化介质。隐私约束与上文 1~4 条完全一致，不因速度采集而放宽。

## 7. 按键速度实时采样通道（M7 新增，PRD 3.10）

### 7.1 为什么需要独立通道

现有的 3 秒 flush 是"增量累加 → 持久化"的链路，服务于今日统计、历史图表、成就系统等"分钟级精度"的业务需求。但 GIF 动效需要"亚秒级响应"（≤ 500 ms 推送一次），如果复用 flush 通道，会导致 GIF 速度更新延迟过高、且与持久化逻辑耦合。

因此在 `InputCaptureWorker` 上**并行增加一个独立的高速推送通道**，与 3s flush 互不干扰：

```
采集线程
├── handleKeyDown
│   ├── keyPresses_++          → 3s flush → DataManager → 今日累计（现有链路）
│   ├── keyTimeBuf_ 写入       → 10s 滑动窗口（新增）
│   └── lastKeyDownMs_ 更新   → 活跃推断 & 空闲判定（复用已有原子变量）
│
├── 3s flush Timer → deltaReady (现有)
│
└── 250ms keySpeedTimer → keySpeedUpdated(cpm) (新增，高速通道)
```

### 7.2 新增成员

```cpp
// InputCaptureWorker.h 新增
private:
    // 按键速度采样（仅采集线程访问，无需锁）
    static constexpr int kSpeedWindowMaxKeys = 200;
    std::array<qint64, kSpeedWindowMaxKeys> keyTimeBuf_{};  // 循环缓冲区
    int keyTimeBufWriteIdx_ = 0;                            // 写入指针

signals:
    // 高速通道：每 250ms 推送一次当前 CPM（跨线程队列信号）
    void keySpeedUpdated(double cpm);

private slots:
    void onKeySpeedTimer();   // 250ms 触发，独立于 onFlushTimer()
```

### 7.3 handleKeyDown 改造

```cpp
void InputCaptureWorker::handleKeyDown(const HookEvent& event) {
    if (event.isAutoRepeat) return;
    if (event.isModifier) { pendingModifiers_ += 1; return; }
    pendingModifiers_ = 0;

    // ---- 以下为 M7 新增 ----
    const qint64 now = QDateTime::currentMSecsSinceEpoch();
    lastKeyDownMs_.store(now, std::memory_order_relaxed);

    // 写入循环缓冲区（仅采集线程写，无需 atomic）
    keyTimeBuf_[keyTimeBufWriteIdx_] = now;
    keyTimeBufWriteIdx_ = (keyTimeBufWriteIdx_ + 1) % kSpeedWindowMaxKeys;
    // ---- M7 新增结束 ----

    keyPresses_.fetch_add(1, std::memory_order_relaxed);  // 原有累加不变
}
```

### 7.4 CPM 计算

```cpp
void InputCaptureWorker::onKeySpeedTimer() {
    const qint64 now = QDateTime::currentMSecsSinceEpoch();
    const qint64 windowStart = now - 3000;  // 最近 3 秒

    int count = 0;
    int total = qMin(keyTimeBufWriteIdx_, kSpeedWindowMaxKeys);
    for (int i = 0; i < total; ++i) {
        if (keyTimeBuf_[i] >= windowStart) { ++count; }
    }

    double cpm = count * 20.0;  // count / 3s × 60s

    // 停手判定：1s 内无按键 → cpm 归零（GIF 约 1.25s 内暂停，不等窗口滑空）
    const qint64 lastKey = lastKeyDownMs_.load(std::memory_order_relaxed);
    if (lastKey > 0 && now - lastKey > 1000) {
        cpm = 0.0;
    }

    emit keySpeedUpdated(cpm);
}
```

### 7.5 暂停/恢复联动

```cpp
void InputCaptureWorker::pause() {
    if (paused_) return;
    flush(QDateTime::currentMSecsSinceEpoch());
    paused_ = true;
    if (keySpeedTimer_) keySpeedTimer_->stop();   // M7：停止速度推送
}

void InputCaptureWorker::resume() {
    if (!paused_) return;
    paused_ = false;
    resetPositionBaseline();
    keyTimeBufWriteIdx_ = 0;                       // M7：清空滑动窗口
    std::fill(keyTimeBuf_.begin(), keyTimeBuf_.end(), 0);
    if (keySpeedTimer_) keySpeedTimer_->start();   // M7：重启速度推送
}
```

### 7.6 start() / stop() 改造

```cpp
bool InputCaptureWorker::start(IPlatformHook* hook) {
    // ... 现有钩子装载 + flushTimer 创建 ...

    // M7：keySpeedTimer 在采集线程内创建（与 flushTimer 同理）
    if (keySpeedTimer_ == nullptr) {
        keySpeedTimer_ = new QTimer(this);
        keySpeedTimer_->setInterval(250);   // 250ms 推送一次
        connect(keySpeedTimer_, &QTimer::timeout,
                this, &InputCaptureWorker::onKeySpeedTimer);
    }
    keySpeedTimer_->start();
    return true;
}

void InputCaptureWorker::stop() {
    // ... 现有 flushTimer + hook 卸载 ...
    if (keySpeedTimer_) keySpeedTimer_->stop();   // M7
}
```

### 7.7 线程安全

| 资源 | 所有者 | 访问者 | 同步 |
|------|--------|--------|------|
| `keyTimeBuf_` | 采集线程 | 采集线程内的 handleKeyDown + keySpeedTimer | 无需同步（单线程读写） |
| `keyTimeBufWriteIdx_` | 采集线程 | 同上 | 无需同步 |
| `lastKeyDownMs_` | 采集线程写 | 采集线程内多处读（活跃推断 + 空闲判定） | `std::atomic<qint64>` |
| `keySpeedUpdated(cpm)` 信号 | 采集线程 | 主线程 AppSettings | Qt 队列信号（跨线程自动排队） |

**关键约束**：`keySpeedTimer_` 必须在 `start()` 中创建（与 `flushTimer_` 同理），确保其线程亲和性为采集线程。在主线程构造函数中创建 Timer 会导致 `QTimer::start()` 触发跨线程告警且定时器不生效（`InputCaptureWorker.cpp` 已有同类坑注释）。

### 7.8 与现有 flush 的关系

两条通道**物理隔离**：
- flush 通道：`std::atomic<int> keyPresses_` 累加 → `flush()` 取交换 → `InputDelta` 经 `deltaReady` 提交
- 速度通道：`keyTimeBuf_` 写入时间戳 → `keySpeedTimer_` 计算窗口内 count → `cpm` 经 `keySpeedUpdated` 推送

唯一共享的资源是 `lastKeyDownMs_`（`std::atomic<qint64>`）——既用于现有活跃推断（§4.3），也用于速度通道的空闲判定。原子类型保证无锁安全。

### 7.9 休眠恢复

系统休眠唤醒后，现有逻辑已调用 `resetPositionBaseline()`（§5）。M7 需追加清空滑动窗口：

```cpp
void InputCaptureWorker::resetPositionBaseline() {
    hasLastPos_ = false;
    keyTimeBufWriteIdx_ = 0;   // M7
    std::fill(keyTimeBuf_.begin(), keyTimeBuf_.end(), 0);
}
```

## 8. 测试要点

- 单元：距离计算（含跳变剔除）、DPI 换算、活跃推断（模拟时间戳序列）。
- **M7 新增**：CPM 计算正确性（注入伪造时间戳序列 → 验证 3s 窗口内 count × 20 = cpm）、空闲判定（模拟长间隔 → cpm 归零）、暂停/恢复后滑动窗口清空、休眠恢复后窗口清空、250ms 定时器在采集线程创建亲和性正确。
- 平台手测脚本：录制宏模拟鼠标轨迹（已知长度）验证误差 < 5%；键盘连打/组合键/长按场景计数正确。
- 边界：休眠恢复、多屏拖拽、远程会话、系统时间回拨（跨天归属）。
