# CursorFlow 性能达标报告（任务 5.3）

> 对应开发计划 [06 §4](06-开发计划与任务拆解.md) 任务 5.3；指标来源 PRD §4 与 [04 §7](04-UI实现方案.md) 性能约束。
> 测量日期：2026-10-30；平台：Windows 10 x64（cl 19.29.30159，Qt 5.15.2 msvc2019_64，Release 构建）。

## 1. 结论摘要

| 指标 | 目标 | 实测 | 结论 |
| ---- | ---- | ---- | ---- |
| 空闲 CPU 占用 | < 1% | **0.05%**（30s 采样） | ✅ 达标 |
| 图表单次重绘（30 点） | < 200ms | **2.00ms** | ✅ 达标 |
| 内存占用（私有工作集） | < 50MB | **68.4MB**（提交 151.5MB） | ❌ 未达标（见 §4 归因） |
| 安装包体积 | < 15MB | 安装目录 **40.92MB** / ZIP 压缩 **16.26MB** | ⚠️ 动态部署不可达，需静态 Qt（05 §4 既定方案） |
| 内存错误/泄漏 | 0 | ASan 环境不可用；Debug CRT 堆检查 **8/8 通过** | ✅ 替代方案通过 |

## 2. 图表渲染计时

- 方法：`TrendChart` 的 `onPaint` 内以 `Date.now()` 记录单次 `requestPaint` 耗时，写入 `lastPaintMs` 属性；`perf_ChartRender` 单测在软件渲染（`QT_QUICK_BACKEND=software`）下断言。
- 数据：近 30 天双序列（距离 + 按键双轴）完整重绘 **2.00ms**，远低于 200ms 阈值（04 §7：Canvas 单帧内一次 requestPaint，禁止循环触发）。
- 附注：HeatmapGrid 与 ParticleTrail 均为按需/定时驱动的轻量 Canvas，无每次输入触发的重绘路径。

## 3. 空闲 CPU 占用

- 方法：应用启动后进入托盘待机（无鼠标键盘操作），30 秒窗口采样进程 CPU 时间。
- 数据：**0.05%**，满足 < 1% 目标。采集钩子仅做原子累加，3s flush 定时器与 UI 无常驻动画（粒子动画仅前台且动效开启时运行，且已验证关闭动效时完全停摆）。
- 附注：M1 验收要求的 24h 连续长稳测试列入 CI 例行监控（06 §7），本报告为短窗口采样。

## 4. 内存占用：未达标归因

- 实测：私有工作集 **68.4MB**，提交内存 151.5MB；关闭动效后 69.3MB，无实质差异（粒子引擎非主因）。
- 归因：Qt Quick 应用在动态链接 Qt 5.15 下的引擎基线（QML 引擎 + 场景图 + QuickControls2）约 60MB+，应用自身增量很小。该目标在「动态部署 Qt」前提下物理上不可达。
- 选项（需评审决策）：
  1. 接受 Qt Quick 基线，将目标修订为「应用增量 < 15MB / 总占用 < 70MB」；
  2. 迁移 QWidget 实现 UI（内存可降至 ~20MB，但放弃现有 QML 视觉方案）；
  3. 静态裁剪编译 Qt Quick（与包体目标同一改造项，内存收益有限）。
- 当前建议：选项 1，理由——空闲 CPU 0.05% 与图表性能均大幅富余，68MB 在 2026 年桌面环境属正常水位。

## 5. ASan / 泄漏检测

- ASan：MSVC ASan 在本机注入环境返回 0xC0000142 无法启动，属环境问题；已列入 CI（ubuntu-clang）执行。
- 替代方案：Debug 构建启用 CRT 调试堆（`_CRTDBG_LEAK_CHECK_DF`）运行全部功能单元测试，**8/8 通过**、退出时无泄漏报告。
- 覆盖范围说明：CRT 堆检查可发现测试路径内的泄漏/越界写，跨平台钩子代码（4.5/4.6）的完整 ASan 验证依赖 CI 矩阵。

## 6. 安装包体积核验（任务 5.4 交叉项）

- windeployqt 动态部署 + 剪裁（Network / VirtualKeyboard / bearer / qmltooling / RemoteObjects / 非SQLite驱动 / 非svg-ico-jpeg编解码器均已移除）后：
  - 安装目录 **40.92MB**（374 文件），部署包冒烟通过；
  - ZIP 压缩近似 **16.26MB**（NSIS LZMA 由 CI 产出，预计略优于 ZIP）。
- 结论：动态链接 Qt 下 < 15MB 不可达（仅 Qt5Core/Quick/Qml/Gui DLL 即超 15MB），达成目标必须采用 [05 §4](05-构建与打包方案.md) 既定的**静态 Qt 裁剪编译**（CI 矩阵执行，超 13MB 预警阈值，06 §6）。

## 7. 测试汇总（截至本报告）

- ctest：**9/10 通过**。唯一失败 `tst_winhook`：Windows 锁屏状态下 SendInput 注入事件无法到达低级钩子，属测量环境限制（需解锁桌面重跑），非代码缺陷；其余功能/性能测试全部通过。
